# Experiment manifest schema (v1.1)

Every experiment directory under `docs/evidence/<campaign>/<datetime-slug>/`
MUST contain a `manifest.yaml` conforming to this schema. The schema is
inspired by MLCommons MLPerf Inference system descriptions, MLflow
tracking metadata, and SLSA/in-toto provenance.

## v1.1 changes vs v1.0

- `image` field is now structured: `registry / repository / tag / digest`.
  `image.ref` (the full path) is OPTIONAL and machine-derived. This makes
  the registry account number a parameter, not a hardcoded value.
- New top-level field `parameters` — defines substitution variables that
  REPRODUCE.md and derived templates reference.

## Why this exists

The schema makes the archive **queryable**. Any new engineer can run:

```bash
# Find every PASS experiment with KV router on Llama-3.1-8B:
yq 'select(.status == "PASS"
       and .config.model == "meta-llama/Llama-3.1-8B-Instruct"
       and ("kv-router" | IN(.config.features[])))' \
   docs/evidence/*/*/manifest.yaml
```

The schema also makes the archive **portable**. The `image.registry`
field is a parameter (`${ECR_REGISTRY}`); the `image.digest` is
canonical (sha256:...) and pins the actual bytes. A downstream
consumer rebuilds from `build-snapshot/`, pushes to their own
registry, and substitutes `${ECR_REGISTRY}` everywhere.

## Required fields

| Field | Type | Example | Why required |
|---|---|---|---|
| `schema_version` | string | `"1.1"` | Future schema migrations |
| `experiment_id` | string (kebab-case) | `kv-router-validation` | Stable identifier for cross-references |
| `campaign` | string | `pr72-rev8` | Group experiments by PR/release |
| `date` | RFC 3339 timestamp | `2026-05-22T10:24:00Z` | Sortable; matches dir name prefix |
| `status` | enum | `PASS` | One of: PASS \| PARTIAL \| FAIL \| DEFERRED \| IN_PROGRESS \| BLOCKED \| SUPERSEDED |
| `image.repository` | string | `dynamo-efa` | Image name (no registry prefix) |
| `image.tag` | string | `520cfc584abb` | Image tag (usually a short git SHA) |
| `image.digest` | string | `sha256:48e6e3104b...` | **Canonical pin** — image cannot be silently re-tagged |
| `git.repo` | string | `dmvevents/awsome-inference-1` | Where the Dockerfile lives |
| `git.commit` | string | `520cfc5` | Exact source state |
| `git.branch` | string | `feature/dynamo-combined-vllm-trtllm-efa` | Aids navigation |
| `hardware.instance_type` | string | `p5.48xlarge` | Required to reproduce |
| `hardware.gpu` | string | `H100` | Quick filter |
| `hardware.node_count` | int | `2` | Multi-node vs single-node |
| `documents.verdict` | string | `VERDICT.md` | Where to find pass/fail analysis |
| `documents.reproduce` | string | `REPRODUCE.md` | Where to find re-run commands |

## Parametric / portable fields

| Field | Type | Example | Notes |
|---|---|---|---|
| `image.registry` | string | `${ECR_REGISTRY}` | Parameter — downstream substitutes their own registry. Default unset. |
| `image.ref` | string (derived) | `${ECR_REGISTRY}/dynamo-efa:520cfc584abb` | Convenience — machine-generated by `make index`; humans should not hand-edit. |
| `image.build_id` | string | `dddf2e17-d482-...` | CodeBuild ID (account-internal; OK to redact in public sync) |
| `parameters` | map | see below | Run-time substitution table |

### `parameters` block (recommended)

```yaml
parameters:
  ECR_REGISTRY: "${ECR_REGISTRY}"
  IMAGE_TAG: "520cfc584abb"
  HF_TOKEN: "${HF_TOKEN}"          # required at runtime, never committed
  AWS_REGION: "us-east-2"
```

REPRODUCE.md and `derived/<template>.yaml` reference these by name. The
shell idiom `${ECR_REGISTRY:-058264135704...}` lets the canonical run
work without setting the var, while letting downstream consumers
override it.

| `hardware.nodes` | string[] | Specific node hostnames in original run (helps debug node-specific failures; OK to redact for public) |
| `hardware.efa_version` | string | EFA stack version |
| `stack.dynamo` | string | Dynamo runtime version |
| `stack.vllm` | string | vLLM version |
| `stack.nixl` | string | NIXL version |
| `stack.libfabric` | string | libfabric version |
| `stack.nccl` | string | NCCL version |
| `config.model` | string | HF model id |
| `config.features` | string[] | Tags: `kv-router`, `disaggregation`, `kv-events`, etc. |
| `config.topology` | string | `single-node` \| `cross-node` \| `multi-node` |

## Status enum

- **PASS** — All test assertions met. Reproducible from these docs.
- **PARTIAL** — Main objective met but with caveats; see VERDICT.md.
- **FAIL** — Test failed. Captured for diagnostic value (often most-cited).
- **DEFERRED** — Test was planned but not executed; see notes for blocker.
- **IN_PROGRESS** — Currently running. Should not exist in main branch — only on a working branch.
- **BLOCKED** — Cannot proceed; depends on external resolution.
- **SUPERSEDED** — Newer experiment replaced this one. Set `parent_experiment_id` to the replacement.

Diagnostic experiments (`FAIL`, `PARTIAL`) are first-class citizens —
they document failure modes and motivate the fixes that PASS
experiments validate.

## Required directory shape

```
<datetime-slug>/
  manifest.yaml         REQUIRED
  README.md             REQUIRED — short narrative, what + why
  VERDICT.md            REQUIRED — pass/fail + numbers
  REPRODUCE.md          REQUIRED — exact commands to re-run
  artifacts/            REQUIRED — IMMUTABLE raw evidence (write-once)
  derived/              OPTIONAL — regenerable analyses + parametric templates
```

`artifacts/` rules:
- Treat as **write-once**. Once committed, never edit files there.
- May contain hardcoded account numbers, IPs, hostnames — that's the
  historical truth of "what we ran". Sanitization belongs in `derived/`.

`derived/` use cases:
- Parametric Kubernetes templates (`dgd-template.yaml` with `${ECR_REGISTRY}`)
- Plots, summaries, analyses regenerable from artifacts/
- Failed-first-attempt directories preserved as cautionary tales (under
  `derived/superseded/<slug>/`)

## Filename convention

Directory: `<UTC-datetime>-<slug>/`
- UTC-datetime: `YYYY-MM-DDTHHMMZ` (ISO 8601 basic — no colons in time)
- slug: kebab-case, descriptive, ≤40 chars
- Examples:
  - `2026-05-21T0900Z-rev7-baseline-rootcause/`
  - `2026-05-22T0550Z-nixlbench-multinode-PASS/`
  - `2026-05-22T1024Z-kv-router-validation/`

## Validation

Run `make validate` from `docs/evidence/` to validate every
manifest.yaml against required fields. Errors halt on first failure
with a yq expression pointing to the missing field.
